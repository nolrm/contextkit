# ContextKit

Set up, update, and tidy this project's AI context. One skill, four modes.

## Usage

```
/ck            # status: what's set up, what needs attention
/ck setup      # first run: analyze the codebase and write the standards
/ck update     # after `ck update`: finish the upgrade and clean up
/ck tidy       # shrink always-loaded context, prune, wire orphan guides
```

Ask questions with options (your multiple-choice tool if you have one — Claude Code `AskUserQuestion`, Codex `request_user_input` — otherwise lettered options). Never edit inside `<!-- Generated by ContextKit -->` … `<!-- End ContextKit -->`; that text belongs to `ck update`.

---

## /ck — Status

1. No `.contextkit/` → tell the user to run `ck install` and stop.
2. Run `ck check` (or read the files directly if the CLI isn't available) and summarise in one table: Installation, Standards (populated / skeleton), Index (`.contextkit/standards/index.md` filled?), Context rules (`context_rules` in `config.yml`), Integrations, Version (`npm view @nolrm/contextkit version` vs `.contextkit/status.json`).
3. If `.contextkit/pending-cleanup.md` exists → recommend `/ck update` first.
4. End with the one next step that matters most.

---

## /ck setup — Write the Standards

Follow `.contextkit/commands/dev/analyze.md` in full. It produces:

- `.contextkit/standards/index.md` — the short always-loaded index (≤ 50 lines): stack, key boundaries, must/must-not rules, and a "when you touch X, read Y" table.
- Topic files in `.contextkit/standards/` holding only what the code can't tell the model.
- `context_rules` in `.contextkit/config.yml` mapping each topic file to the paths it applies to. Then run `ck update --force` (or `ck <platform>`) so the CLI renders path-scoped rules for each installed tool.

---

## /ck update — Finish an Upgrade

Run after `ck update`. The CLI does the mechanical part (inside markers only) and leaves anything that needs judgment in `.contextkit/pending-cleanup.md`.

1. **Clean tree first.** If `git status --porcelain` shows changes, stop and ask the user to commit or stash.
2. If `ck update` hasn't run for the installed CLI version, run it now.
3. Work through `.contextkit/pending-cleanup.md` item by item:
   - **Custom content in `CLAUDE.md`** (outside the ContextKit block) → for each block, ask: **Move to `AGENTS.md`** (shared by every tool) / **Keep in `CLAUDE.md`** (Claude-only) / **Delete**. Moved content goes in `AGENTS.md` outside the ContextKit block.
   - **Unfinished squad handoff** (`.contextkit/squad/`) → ask: **Convert to a goal** (write `.contextkit/goals/<slug>.md` from the PO spec's acceptance criteria as Outcomes, mark finished ones done) / **Archive** (move to `.contextkit/archive/squad/`) / **Keep as is**.
   - **Spec folder** (`.contextkit/spec/`) → ask: **Convert open stories to goals** / **Archive** / **Keep**.
   - **Squad CI workflow** (`.github/workflows/squad-issue.yml`) → it can no longer run. Ask: **Delete** / **Keep**.
   - **Pending standards updates** (`pending_standards_updates` in `config.yml`) → for each entry, read the file and that version's `CHANGELOG.md` entry, fold the upstream fix into the customised text, show the change, then remove the entry.
   - **Stale references** reported by `ck check --context` → fix each one (point at the new skill or file, or delete the line).
4. Delete `.contextkit/pending-cleanup.md` once every item is resolved.
5. Run `ck check --context` again; it should be clean.
6. Commit once: `chore(contextkit): upgrade to <version>`. Don't skip hooks.
7. Reply with a short list: what moved, what was archived, what was deleted, anything left.

## /ck tidy — Keep Context Lean

Always-loaded context costs tokens every session and dilutes what matters.

1. **Measure.** `wc -l` the always-loaded set: `AGENTS.md`, `CLAUDE.md`, `.contextkit/standards/index.md`, and `.claude/rules/*.md` files without `paths:`. Report the total.
2. **Prune generic rules.** Remove rules the model would follow anyway from the surrounding code, or that a linter/formatter already enforces (indentation, quotes, semicolons, naming the code already shows). Keep anything project-specific.
3. **Densify.** Short bullets, no repeated rationale, examples only where a rule is ambiguous. Preserve every rule — cut words, not meaning. Diagrams only if `diagrams_in_docs: true` in `config.yml`.
4. **Keep the index short.** Move topic detail from `index.md` into the right topic file; leave a pointer row in the "read when" table.
5. **Wire orphan guides.** List `.md` files in `.contextkit/standards/` (and `docs/` guides written for the AI) that nothing loads — not in the index table, not in `context_rules`. For each, propose paths and ask before adding it to `context_rules`. Then run `ck update --force` to render the rules.
6. **Promote repeated corrections.** In `.contextkit/corrections.md`, a mistake logged twice or more becomes a rule in the matching topic file (`/learn` style).
7. **Re-measure** and report before/after lines and what changed. Check that every rule present before is still present (possibly reworded) after.
