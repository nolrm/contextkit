# Compress

Rewrite a file for information density while preserving rules/meaning, then report the before/after diff.

## What I'll Do

1. Resolve the target file(s) from the argument.
2. Measure current size: `wc -l` and `wc -w` on the target (same method as the Measured Baseline in `docs/token-efficiency.md` — no bespoke tooling).
3. Classify the target:
   - **Bridge file** (contains `<!-- Generated by ContextKit -->` / `<!-- End ContextKit -->`, e.g. `CLAUDE.md`, `AGENTS.md`) → Marker Safety applies.
   - **Generated Skill file** (`.claude/skills/*/SKILL.md`, `.codex/skills/*/SKILL.md`) → Backup Before Editing applies.
   - Plain standards/doc file → neither special rule applies, rewrite in place.
4. Rewrite for density: no Mermaid unless requested, minimal tables, short bullets, selective examples, no repeated rationale. Preserve every rule/behavior — cut words, not meaning.
5. If the target is a README/doc file under the Documentation Levels and it's still over the relevant threshold after densifying, don't compress further — apply the Length Check split rule from `.contextkit/commands/docs/doc-arch.md` / `doc-feature.md` / `doc-component.md` instead (propose the split, wait for confirmation).
6. Re-measure (`wc -l` / `wc -w` again).
7. Compliance check: list every rule/heading present before compression; confirm each still appears (possibly reworded) after. Flag anything dropped rather than reworded.
8. Report: before/after line count, word count, % reduction, and a short list of what was condensed and why.

## Marker Safety (bridge files only)

- Locate both `<!-- Generated by ContextKit (@nolrm/contextkit) ... -->` and `<!-- End ContextKit -->` (also legacy `<!-- Generated by ContextKit -->` / `<!-- Generated by Vibe Kit -->` variants).
- Edit ONLY the content between the markers. Leave everything before/after byte-for-byte unchanged.
- If either marker is missing → STOP. Do not guess or rewrite the whole file. Tell the user to run `ck update` instead.

## Backup Before Editing Generated Files

- Before touching `.claude/skills/*/SKILL.md` or `.codex/skills/*/SKILL.md`, copy the file to `<path>.bak-<timestamp>` first.
- If the file's frontmatter/body looks hand-customized (diverges from what the shipped template would produce), flag this to the user before compressing rather than silently overwriting.

## How to Use

```
/compress .contextkit/standards/testing.md
/compress .contextkit/corrections.md
```

## Standards Applied

- Documentation Levels split rule (see `.contextkit/commands/docs/doc-arch.md` Length Check) for retrofitting oversized docs.
